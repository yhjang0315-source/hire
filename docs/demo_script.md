# 시연 동선과 녹화 대본 — 커리어 사다리

2차 기능심사·본선 시연용. **3분 기본 대본**을 먼저 녹화하고, 시간이 더 주어지면 **확장 장면**을 이어 붙인다.
화면 문구는 모의데이터 기준 실제 출력(2026-09-30 확인)이다. 데이터·문구를 바꾸면 이 문서도 함께 고친다.

## 1. 녹화 전 준비

1. 앱 실행
   ```bash
   cd web && npm install && npm run build && npx next start -p 3000
   ```
2. 브라우저: Chrome 개발자 도구 → 기기 모드 → **폭 420px 안팎(모바일)**, 확대 100%
3. 초기화: 마이페이지 → 재진단 기록 → **기록 지우기**(이전 연습 기록이 보이지 않게)
4. 인터넷 연결 확인: 공고 지도 배경(OpenStreetMap)은 온라인에서만 보인다. 끊겨도 마커·목록은 동작한다.
5. 탭을 미리 열어 두기(장면 전환 시간 절약)

   | 탭 | 주소 |
   |---|---|
   | ① 홈 | `/` |
   | ② 입력 | `/input` |
   | ③ A12 결과 | `/result?persona=P-A12` |
   | ④ C33 결과 | `/result?persona=P-C33` |
   | ⑤ B07 결과 | `/result?persona=P-B07` |
   | ⑥ 상담사 | `/counselor` |

6. 모의면접 답변은 미리 복사해 두고 붙여넣는다(타이핑 시간 절약).
   > 설계팀 인턴 6개월 동안 솔리드웍스로 부품 30개를 모델링했고, 도면 검토에서 공차 오류 5건을 찾아 수정했습니다. 꼼꼼하게 확인하는 습관이 강점입니다.

## 2. 전하려는 메시지 3가지

1. **탈락 원인부터 진단한다** — 같은 "불합격"도 요건 부족·서류 표현·조직 적합으로 나뉘고, 처방이 다르다.
2. **공고 하나가 아니라 목표까지의 사다리를 준다** — 부족한 역량을 훈련만이 아니라 *일자리*로 채우는 경로.
3. **설득한다** — 판단 근거와 이후 계획을 함께 보여 줘, 추천을 받아들일 수 있게 한다.

## 4. 확장 장면(시간이 더 있을 때, 장면당 20~40초)

1. **커리어 경로** `/path?persona=P-A12` — "지금 → D사 품질관리 → F사 설계 보조 → Q사 기계설계"
   - 역량 충족도가 25%에서 63%로 오르고, 새로 채우는 역량(+ 문제 해결 등)이 함께 표시된다.
   - 경력 발판 단계는 역량 대신 경력 인정 가능성 70을 보여 준다.
   - 마지막 단계에는 남은 요건(일반기계기사)이 나온다.
2. **공고·기업 상세** `/posting/MOCK-D01?persona=P-A12` — 우대 조건 ✓ 표시, 같은 지역 직종별 구인배수 차트(품질·설비 정비 1.63 강조, 막대에 손 올리면 구인·구직 수)
3. **공고 지도** `/map?persona=P-A12` — 단계별 색·기호 마커, 1순위 큰 마커, 단계 칩으로 걸러 보기, 목록 누르면 지도 이동
4. **목표 직종 비교** `/compare?persona=P-A12` — 기계설계·품질관리·CAD를 나란히, "지금 지원하기 가장 수월한 직종은 품질관리 검사원… 채용 수요(구인배수 1.63)도 가장 높아요"
5. **훈련과정** `/training?persona=P-A12` — 부족 역량(주황 = 목표 공고 우대 조건, 회색 = 직업정보 핵심 역량)과 이를 채우는 내일배움카드 과정
6. **마이페이지** `/my?persona=P-A12` — 마감 임박·경력 발판 알림, 결과별 지원 현황, 재진단 기록
7. **결과 입력으로 재진단** — 결과 입력·수정에서 지원 결과를 바꾸면 진단 유형과 추천이 바로 바뀌는 것 보여 주기
8. **상담사 필터** `/counselor?f=focus` — 집중지원 5명, 구직자 선택 → 상담 일정 잡기(시연)

## 5. 예상 질문과 답변

1. **실제 데이터로도 되나요?**
   - 수집 CLI와 정규화가 준비돼 있다.
   - 공공데이터포털·고용24 Open API 인증키를 넣으면 같은 화면이 수집 데이터로 동작한다(`DATA_SOURCE=cache`).
   - 항목명은 API 명세로 대조한다.
2. **AI는 어디에 쓰나요?**
   - 점수·진단·수치는 규칙 엔진이 계산해 설명 가능하게 한다.
   - 생성형 AI는 다섯 곳을 맡는다: 경력 인터뷰 역량 추출, 공고 인재상 추출, 추천 카드 문장, 서류 첨삭, 모의면접.
   - 연결 지점은 이미 함수로 분리돼 있다. 제공되는 AI 플랫폼으로 바꾸면 된다.
3. **진단이 틀리면요?**
   - 결과가 3건 미만이면 '판단 보류'로 두고 기록을 더 받는다.
   - 결과를 입력할 때마다 재진단한다.
   - 근거(지원 이력·요건 충족도)를 화면에 그대로 보여 줘, 본인이 판단할 수 있게 한다.
4. **눈을 낮추라는 건가요?**
   - 서류 표현형·조직 적합형은 같은 수준 공고에 다시 도전하게 한다.
   - 자격 격차형만 목표로 이어지는 단계를 제안한다.
   - "눈을 낮춰" 같은 표현은 문장 생성 단계에서 금지어로 막는다.
5. **고용24 기존 서비스와 뭐가 다른가요?**
   - 기존 추천은 조건이 맞는 공고를 보여 준다.
   - 이 서비스는 **왜 떨어졌는지**부터 진단하고, 목표까지의 경로와 설득 근거를 준다.
6. **개인정보는요?**
   - 가명 ID로 동작하고, 입력 상태는 서버에 저장하지 않는다(주소창에 인코딩).
   - 재진단 기록은 이 기기 브라우저에만 저장된다.

## 6. 녹화 팁

1. 장면 사이 전환은 미리 연 탭으로 바꾸고, 스크롤은 천천히 한 번만.
2. 추천 카드의 "한마디 → 근거 → 계획" 순서가 핵심이라 멈춰서 읽어 준다.
3. 화면 하단 "시연: 규칙 기반…" 안내 문구는 가리지 않는다(심사위원이 모의·실서비스 범위를 알 수 있게).
4. 녹화 후 확인: 3분 이내, 페르소나 이름(A12·C33·B07)과 진단 유형이 화면·내레이션에서 일치하는지.
