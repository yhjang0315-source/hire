# 마감메이트 기획 — v0.1

> SNU × Croche 해커톤 출품작 · 신청서: [application_draft.md](application_draft.md)

## 1. 한 줄 정의

녹강·과제 파일을 올리면 AI가 할 일과 소요 시간을 뽑고, **내 스타일에 맞춘 스케줄**을 짠 뒤, 시작할 때 작업 창을 띄우고 **날짜와 진행률에 따라 캐릭터가 압박**하는 대학생 마감 관리 앱.

## 2. 문제와 사용자

1. **녹강**: 수강 인정 기간 안에 들어야 출석이 인정되는데, 과목마다 기간이 달라 놓치기 쉽다.
2. **과제**: 여러 과목에서 한꺼번에 쏟아져 까먹고, 얼마나 걸릴지 몰라 계획을 세우기 어렵다.
3. **계획**: 세워도 밀리면 다시 짜기 귀찮아 포기한다.
4. **대상**: 녹강·과제를 동시에 관리해야 하는 대학생 (예: 녹강 3과목 + 과제 4개 + 주 2회 알바)

## 3. 핵심 흐름

1. **입력**: 고정 일정(시간표·알바) + 과제·공지 파일 또는 직접 입력
2. **분석**: AI가 과제 카드 생성(유형·마감·분량·소요 시간), 애매하면 되묻기
3. **스케줄**: 스타일에 맞춰 빈 시간에 작업 블록 배치
4. **작업 창**: 시작 시점에 필요한 자료와 첫 할 일을 모아 띄움 + 타이머
5. **압박**: 남은 날짜 × 진행률로 캐릭터 단계 결정
6. **보정**: 타이머 기록으로 스타일 수치 갱신 → 밀린 블록 자동 재조정

## 4. 기능 상세

### 4.1 입력

| 항목 | 내용 |
|---|---|
| 고정 일정 | 수업 시간표(에브리타임 캡처 → AI 추출), 알바·동아리 직접 입력, 기상·취침 시각 |
| 과제 파일 | 과제 안내 PDF·이미지, 공지 캡처, 직접 입력 |
| 녹강 | 수강 인정 기간, 영상 길이, 출석 인정 조건(예: 90% 이상 시청), 평소 배속 |
| 과제 유형 | 보고서 / 문제풀이 / 코딩 / 발표자료 / 팀플 / 시험 준비 / 녹강 |
| 되묻기 | 추출 신뢰도가 낮은 항목만 확인 질문 (예: "제출 시각이 23:59 맞나요?") |

### 4.2 스타일 모델

| 수치 | 뜻 | 처음 값 | 보정 방법 |
|---|---|---|---|
| 시작 성향 | 마감 며칠 전에 시작하는지(미리형 ↔ 몰아형) | 설문 | 실제 첫 타이머 시작일 |
| 보정 배율(유형별) | 예상 대비 실제 걸린 시간 (예: 코딩 2.0, 보고서 1.2) | 설문(전체 1개) | 과제 완료 시 타이머 합계 ÷ AI 예상 |
| 집중 지속 시간 | 한 번에 끊지 않고 하는 시간 | 설문 | 타이머 한 회 평균 길이 |
| 선호 시간대 | 집중이 잘 되는 시간 | 설문 | 블록 완료율이 높은 시간대 |

**온보딩 설문 5문항**

1. 과제를 보통 마감 며칠 전에 시작하나요? (7일 이상 / 3~6일 / 1~2일 / 당일)
2. 조금씩 나눠 하는 편인가요, 한 번에 몰아 하는 편인가요?
3. 한 번에 집중할 수 있는 시간은? (30분 / 1시간 / 2시간 / 3시간 이상)
4. 과제가 예상보다 얼마나 더 걸리나요? (비슷 / 1.5배 / 2배 이상)
5. 집중이 잘 되는 시간대는? (아침 / 오후 / 저녁 / 새벽)

### 4.3 스케줄링 (규칙 기반)

1. **가용 시간** = 기상~취침 − 고정 일정 − 이동·휴식 여유
2. **필요 시간** = AI 추정 시간 × 유형별 보정 배율
   - 녹강 = 영상 길이 ÷ 배속 + 정리 시간, 마감 = 수강 인정 기간 종료일
3. **시작 시점**
   - 미리형: 필요 일수 + 여유 2일 전부터
   - 몰아형: 마감 가까이 몰되, 안전선(D-2) 전에 첫 블록 1개는 배치
4. **블록 배치**: 한 칸 ≤ 집중 지속 시간, 선호 시간대 우선
5. **우선순위** = 마감 임박도 × 필요 시간 × 성적 반영 비중
6. **자동 재조정**: 놓친 블록은 남은 가용 시간에 다시 배치
7. **과부하 경고**: 필요 시간이 가용 시간보다 많으면 알리고 선택지 제안
   - 예: "이번 주 6시간 부족해요 → ① 주말 3시간 추가 ② C 과제는 최소 분량 ③ 녹강 1.5배속"

### 4.4 작업 창

1. **띄우는 시점**: 스케줄상 첫 블록 시작 시각 (알림 → 탭하면 열림)
2. **구성**
   1. 과제 원문 요약과 제출 형식 체크리스트
   2. 관련 파일·녹강 링크
   3. "첫 15분 할 일" (AI가 과제를 쪼갠 첫 단계)
   4. 타이머 (시작·일시정지·완료) → 실제 소요 시간 자동 기록

### 4.5 압박 단계 (날짜 × 진행률)

**진행률** = 지금까지 끝낸 블록 시간 ÷ 계획상 지금까지 끝냈어야 할 블록 시간

| 진행 상태 \ 남은 날짜 | 시작 전 | 진행 구간(~D-3) | 임박(D-2~D-1) | 당일 |
|---|---|---|---|---|
| 앞섬 (110% 이상) | 시작 예고 | 0 칭찬 | 0 칭찬 | 1 다정(마무리 확인) |
| 계획대로 (80~110%) | 시작 예고 | 1 다정 | 1 다정 | 2 잔소리 |
| 뒤처짐 (80% 미만) | — | 2 잔소리 | 3 협박 | 3 협박 |
| 미착수 (시작 시각 지남) | — | 2 잔소리 | 3 협박 | 3 협박 |

- 단계가 오를수록 알림 빈도와 캐릭터 표정 강도가 올라간다.
- 경고 문구는 단계 + 과제명 + 남은 작업량으로 AI가 생성한다.

## 5. AI와 규칙의 역할 분담

| 기능 | 담당 | Croche 기능 영역 |
|---|---|---|
| 파일·캡처에서 과제·시간표 추출, 되묻기 | AI | 표준 Tool(파일 읽기), Context·Session |
| 과제 유형 분류, 소요 시간 추정, 첫 15분 할 일 | AI | 모델 추천(고성능, 과제당 1회) |
| 스타일 수치 저장·보정 | 규칙 + 저장 | Memory·상태 관리 |
| 스케줄 배치, 재조정, 과부하 계산 | 규칙 | Tool 인터페이스(알고리즘을 Tool로 등록) |
| 압박 단계 결정 | 규칙 | — |
| 경고·칭찬 문구 | AI | 비용 제어(경량 모델) |

## 6. 3일 MVP와 시연

### 6.1 개발 범위

| 날짜 | 작업 |
|---|---|
| 10.14 | 입력(파일 업로드 → AI 추출, 직접 입력, 시간표), 과제 카드, 되묻기 |
| 10.15 | 온보딩 설문, 스케줄 배치·재조정·과부하 경고, 주간 스케줄표 화면 |
| 10.16 | 작업 창 + 타이머, 압박 캐릭터 4단계, 로컬 알림, 시간 빨리 감기, 시연 데이터 |

### 6.2 시연 시나리오 (3분)

1. 공지 PDF 2개 + 녹강 캡처 업로드 → 과제 카드 자동 생성, 되묻기 1회
2. 같은 과제로 미리형 vs 몰아형 스케줄표 비교
3. 빨리 감기 → 첫 블록 시각에 작업 창 → 타이머 시작
4. 블록 하나를 놓침 → 자동 재조정, 과부하 경고와 선택지
5. D-1 뒤처짐 → 캐릭터 협박 단계 알림
