# 1차 기획안 목차 (PDF 10쪽 이내) — v0.1

> 기준 문서: [service_design.md](service_design.md) · 제출 마감: 2026-10-13(화)
> 공식 기획안 양식이 있으면 그 틀을 우선하고, 아래 내용을 양식 항목에 맞춰 재배치한다.

## 쪽별 구성

| 쪽 | 제목 | 핵심 메시지 | 들어갈 내용 | 준비할 자료 |
|---|---|---|---|---|
| 1 | 표지·한 줄 요약 | "추천이 아니라 목표까지 가는 길을 보여준다" | 서비스명, 한 줄 정의, 대표 화면 1장, 참가자 | 대표 화면 목업 |
| 2 | 문제 정의 | 신입은 '경력 있는 신입'의 벽에서 막힌다 | 문제 4가지(경력 요구, 단편적 탐색, 탈락 원인 불명, 설명 없는 추천), 페르소나 A·B | EIS 직종별 구인배수, 신입 공고 비중 |
| 3 | 현황 분석 | 기존 서비스는 '맞는 직업'까지만 알려준다 | 잡케어·취업확률 컨설팅·민간 비교표, 빈틈 3가지 | 설계 문서 3장 표 |
| 4 | 서비스 개요 | 진단 → 두 갈래 추천 → 설득과 계획 | 핵심 기능 3가지: ① 탈락 원인 진단 ② 단계별 공고 추천(사다리/방향 전환) ③ 추천 카드(한마디·근거·계획) | 서비스 흐름도 |
| 5 | 사용자 시나리오 | 같은 탈락, 다른 처방 | 페르소나 A(자격 격차형) vs B(조직 적합형) 화면 흐름과 추천 카드 예시 | 화면 목업 2세트 |
| 6 | 핵심 로직 | 판단은 데이터로, 설명은 AI로 | F·T·C·S 점수, 진단 규칙표, 단계 분류 조건 | 설계 문서 7~9장 |
| 7 | AI 활용과 신뢰 | AI는 사람마다 다른 설명을 만든다 | AI와 규칙의 역할 분담, 환각 방지, 말투·윤리 원칙, 개인정보 | 설계 문서 12~13장 |
| 8 | 데이터 활용 | 고용24 데이터 5종을 핵심 로직에 사용 | API별 용도 매핑표, 데이터 흐름도 | API 명세 확인 결과 |
| 9 | MVP 개발 계획 | 2주 안에 핵심을 작동시킨다 | 구현 범위(포함/확장), 2주 일정, 기술 구성, 시연 시나리오 | 일정표 |
| 10 | 기대효과·확장 | 고용24 AI 고용센터의 한 축 | 정량 지표(지원 대비 합격률, 목표 직종 도달률, 재방문율), 정책 연계(고용센터 개편, 잡케어 연동), 확장 로드맵 | 지표 정의 |

## 9쪽 MVP 2주 일정 초안

| 기간 | 작업 |
|---|---|
| 1~2일 | API 연동(채용정보·직업정보·학과정보·훈련과정·EIS), 시연 목표 직종 3~5개 데이터 캐시 |
| 3~5일 | 점수 계산(F·T·C·S), 진단 규칙, 단계 분류 |
| 6~8일 | AI 기능: 역량 구조화, 공고 역량·인재상 추출, 추천 카드 문장 생성 |
| 9~11일 | 화면 3개(입력·결과·지원 결과 입력), 성향 자가진단 |
| 12~13일 | 페르소나 A·B 시나리오로 검증, 임계값 조정 |
| 14일 | 시연 영상·발표자료 |

## 작성 전 확인할 것

1. 공모전 홈페이지의 공식 심사기준과 기획안 양식
2. EIS 근거 수치(2쪽 문제 정의용)
3. 직업정보·EIS·강소기업 API 제공 항목(8쪽 데이터 활용용)
4. 서비스명 확정
